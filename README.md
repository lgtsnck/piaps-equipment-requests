# Учёт и обработка заявок на приобретение оборудования

Учебный проект по дисциплине **«Проектирование и архитектура программных систем» (ПиАПС)**.

Цель проекта — спроектировать информационную систему регистрации, согласования и обработки заявок подразделений на приобретение оборудования, реализовать программный прототип и проверить его соответствие установленным требованиям.

**Предметная область** — адаптированный вариант № 3 лабораторного практикума «Проектирование информационных систем», связанный с учётом основных средств в отделе материально-технического снабжения (МТС). В проекте рассматривается учёт заявок **на приобретение оборудования**. Четыре лабораторные работы выполняются последовательно в рамках одного проекта.

## Назначение и границы системы

Предусмотрены три роли — **заявитель**, **руководитель МТС** и **специалист МТС**. Основной процесс включает создание заявки, проверку данных, согласование или возврат на уточнение, назначение исполнителя, обработку и закрытие. Также предусмотрена возможность отклонения заявки с указанием причины.

Все пользователи могут создавать собственные заявки, редактировать их в допустимых состояниях и отправлять на согласование. Обычные сотрудники видят заявки своего подразделения, руководитель и специалисты МТС — заявки всех подразделений. Единственный руководитель МТС может согласовывать в том числе собственные заявки. Начать обработку и закрыть заявку может только назначенный специалист.

Выбор текущего пользователя выполняется из демонстрационного справочника без полноценной аутентификации. Проверки полномочий реализованы на уровне бизнес-логики. Фактические закупки, платежи, бухгалтерский и складской учёт, а также интеграции с поставщиками и внешними системами в учебный прототип не входят.

## Технологии

| Назначение | Инструмент |
| --- | --- |
| Язык программирования | Python 3.14 |

## Подготовка окружения и запуск

Для первоначальной настройки нужен установленный [uv](https://docs.astral.sh/uv/). Выполнить:

```powershell
git clone https://github.com/lgtsnck/piaps-equipment-requests.git
cd piaps-equipment-requests
uv sync
uv run python --version
```

Для проверки доступности Tkinter можно выполнить:

```powershell
uv run python -m tkinter
```

Для запуска прототипа из корня проекта используется команда:

```powershell
uv run python -m equipment_requests
```

При первом запуске создаётся локальная база данных `requests.db`, если она отсутствует. Сохранённые заявки доступны при повторном запуске. Файл базы данных и виртуальное окружение `.venv/` не включаются в репозиторий.

## Текущее состояние

Подготовлены анализ предметной области, функциональные и нефункциональные требования, сценарии обработки заявок и семь UML-моделей. Реализован работающий прототип с графическим интерфейсом и постоянным хранением данных в SQLite. Требования и UML-модели актуализированы в соответствии с согласованной реализацией.

На этапе ЛР № 4 предстоит реализовать автоматизированные тесты, зафиксировать результаты проверок, оценить архитектуру по сценариям изменения требований и завершить пояснительную записку.
