# Учёт и обработка заявок на приобретение оборудования

Учебный проект по дисциплине **«Проектирование и архитектура программных систем» (ПиАПС)**.

Цель проекта — спроектировать информационную систему регистрации, согласования и обработки заявок подразделений на приобретение оборудования, реализовать небольшой программный прототип и проверить его соответствие требованиям.

**Предметная область** — адаптированный вариант № 3 из методических указаний по лабораторному практикуму — учёт движения основных средств в отделе материально-технического снабжения (МТС). Работа выполняется по требованиям четырёх лабораторных работ преподавателя.

## Границы проекта

Система предусматривает три роли — **заявитель**, **руководитель МТС** и **специалист МТС**. Основной процесс включает создание и проверку заявки, согласование или возврат на уточнение, назначение специалиста, обработку и закрытие. Предусмотрена возможность отклонения заявки.

Реальные закупки, бухгалтерский учёт, расчёты с поставщиками и интеграции с внешними системами в учебный прототип не входят.

## Установка и проверка окружения

Необходим установленный [uv](https://docs.astral.sh/uv/). Из корня проекта выполнить:

```powershell
uv sync
uv run python --version
uv run python -m tkinter
```

Последняя команда открывает тестовое окно Tkinter. Команда запуска самого приложения появится после реализации прототипа.

## Документация и лабораторные работы

Работы выполняются в рамках **одного проекта**, отдельные приложения под каждую лабораторную не создаются.

| Этап | Содержание | Статус |
| --- | --- | --- |
| ЛР № 1 | Анализ предметной области, требования, сценарии и Activity-диаграмма | В работе |
| ЛР № 2 | UML Use Case, Class, Activity, State Machine и Sequence | Запланировано |
| ЛР № 3 | Архитектура, Component, Deployment и прототип | Запланировано |
| ЛР № 4 | Доработка, тестирование и оценка архитектуры | Запланировано |

Развёрнутая текстовая часть и результаты лабораторных работ будут объединены в `docs/README.md` (пояснительная записка в Markdown), итоговый вариант планируется оформить в DOCX.

Сейчас доступен исходник [диаграммы деятельности обработки заявки](docs/diagrams/activity/activity.puml). Другие ссылки на диаграммы, код и результаты тестирования будут добавляться по мере появления соответствующих файлов.
